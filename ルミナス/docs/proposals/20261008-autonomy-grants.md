## 0. 審査で分かった大事な事実

1. **クラウドのこのセッションでは、ルミナスの hooks と権限の設定が読み込まれていなかった。** セッションはルミナスのフォルダの外（`/home/user`。10-07 の前半はリポジトリの根）から始まり、`ルミナス/.claude/settings.json` を読んでいない（開始時に作られるはずの `state/.sessions/<id>.start` が 1 件も無い。終了時に走ったのは環境側の git の確認だけで、ルミナスの Stop gate は一度も走っていない）。CLAUDE.md 冒頭の「hooks と権限は、このフォルダでセッションを開始したときに有効」のとおりで、クラウドの既定の起点では無効になる。Mac の正本のフォルダで `claude` を起動したときに効く見込み（§1-1 で確かめる）。なお git の pre-commit・pre-push（鍵の検査）は、このクローンでも `core.hooksPath` が設定されていて働いている
2. そのため、保護ファイルの守り（編集の確認・Bash の書き込みの禁止・開始時の未承認の差分の警告）は、クラウドの司令塔には効いていない。今日 `VIRTUAL_MARK.md` の書き換えを止めたのは、ルミナスの設定ではなく Claude Code の自動モードの安全確認だった
3. 「Mark がチャットで指示したら司令塔が 1 行足す」では、偽の指示を見分けられない。別のセッションからの連絡・予約した通知・PR の通知・圧縮後の要約・HANDOVER に書かれた「Mark の指示」は、どれも次のセッションでは指示に見える
4. 全体の停止の印は、その機械の中にしかない（Mac で止めてもクラウドは止まらない。逆も同じ）

## 1. 適用の前提（この順で満たす）

1. **hooks が効く環境を確かめる**: Mac の正本で `claude` を起動し、`state/.sessions/` に開始の印ができること・`/hooks` にルミナスの hooks が並ぶことを確かめ、HANDOVER に書く。クラウドでも効かせるかは Mark が決める（§5-2）
2. **全体の停止を実装して確かめる**: `docs/specs/20261008_global_halt.md` の A と B を実装・審査し、Mac で実際に止まることを確かめる
3. **台帳の変更を Mark 自身の操作に限る方法を決めて、用意する**（§5-3）。推奨の (a) なら、Mark 本人が、毎回 Mark の操作（Touch ID かハードウェアの鍵）が要る署名の鍵を作り、その指紋を保護ファイルに固定し、guard-protected で鍵と署名の操作を止める（§5-3）
4. その後に、下の差分を Mark の承認で適用する。台帳は空から始まる
