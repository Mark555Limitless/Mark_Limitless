## 0. 審査で分かった大事な事実

1. **クラウドのこのセッションでは、ルミナスの hooks と権限の設定が読み込まれていなかった。** セッションは `/home/user` から始まり、`ルミナス/.claude/settings.json` を読んでいない（開始時に作られるはずの `state/.sessions/<id>.start` が 1 件も無い。終了時に走ったのは環境側の git の確認だけで、ルミナスの Stop gate は一度も走っていない）。CLAUDE.md 冒頭の「hooks と権限は、このフォルダでセッションを開始したときに有効」のとおりで、クラウドの既定の起点では無効になる。Mac の正本のフォルダで `claude` を起動したときにだけ効く
2. そのため、保護ファイルの守り（編集の確認・Bash の書き込みの禁止・開始時の未承認の差分の警告）は、クラウドの司令塔には効いていない。今日 `VIRTUAL_MARK.md` の書き換えを止めたのは、ルミナスの設定ではなく Claude Code の自動モードの安全確認だった
3. 「Mark がチャットで指示したら司令塔が 1 行足す」では、偽の指示を見分けられない。別のセッションからの連絡・予約した通知・PR の通知・圧縮後の要約・HANDOVER に書かれた「Mark の指示」は、どれも次のセッションでは指示に見える
4. 全体の停止の印は、その機械の中にしかない（Mac で止めてもクラウドは止まらない。逆も同じ）

## 1. 適用の前提（この順で満たす）

1. **hooks が効く環境を確かめる**: Mac の正本で `claude` を起動し、`state/.sessions/` に開始の印ができること・`/hooks` にルミナスの hooks が並ぶことを確かめ、HANDOVER に書く。クラウドでも効かせるかは Mark が決める（§5-2）
2. **全体の停止を実装して確かめる**: `docs/specs/20261008_global_halt.md` の A と B を実装・審査し、Mac で実際に止まることを確かめる
3. **台帳の変更を Mark 自身の操作に限る方法を決める**（§5-3）
4. その後に、下の差分を Mark の承認で適用する。台帳は空から始まる

## 2. 考え方

- 憲章 CHARTER I-5 は、取り消せない操作を「Mark の明示的な許可、または事前に文書化された自走範囲（`VIRTUAL_MARK.md`）内」でなら行えるとしている。憲章は変えない
- 今の `VIRTUAL_MARK.md` §3 は、公開・送信・課金・削除を**常に**確認の側に置いている。これを、**Mark が台帳に載せた範囲の中なら確認なしで行える**ように変える
- 仮想Mark の推測で範囲は広がらない。台帳の行を足す・変える・消すのは Mark だけ。取り消し（止める方向）は別の追記専用の記録で誰でもできる
- **行を使ってよいのは、hooks と停止が効くと確かめた環境（当面は Mac の正本）の司令塔だけ**。クラウドのセッション・サブエージェント・外部AIは使えない

## 5. Mark に決めてほしいこと

1. **順番**: §1 の前提（hooks の確認 → 全体の停止の実装と確認 → 台帳の変更の方法）を先に満たしてから適用する、でよいか（推奨: はい）
2. **クラウドでも hooks を効かせるか**: (a) 効かせない。台帳はクラウドでは使わない（推奨。簡単で安全）／(b) 効かせる（リポジトリの根に設定を置くなど。環境の設定の変更で、公開リポジトリの他のものにも影響しうる）
3. **台帳を「Mark 自身の操作」で変える方法**:
   - (a) Mac の正本で、司令塔が出した文面を Mark が確認画面で見て許可し、続けて Mark が端末で承認タグを付ける（`luminous-approved-*`。署名の設定が要る。既存の仕組みと同じ）
   - (b) Mark が GitHub の Web 画面で `VIRTUAL_MARK.md` を直接編集する（Mark のアカウントのコミットになる。ただし Claude の GitHub の道具でも同じ形のコミットを作れるおそれがあり、見分け方は要検討）
   - (c) (a) の承認タグなしで、Mac の確認画面の許可だけ（簡単だが、コミット済みの改ざんを後から見分けられない）
   - 推奨: (a)。署名の設定は司令塔が手順を書く
4. 最初に台帳に載せたい操作（前提を満たした後で）
