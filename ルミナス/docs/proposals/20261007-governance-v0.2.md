## リポジトリの外で Mark が行う設定（推奨・任意）

1. 権限の上限を固定する: Mark の `~/.claude/settings.json`（または組織の managed settings）に
   `"permissions": { "disableBypassPermissionsMode": "disable" }` を入れる（推測: 項目名は公式文書で要確認）。
   サブエージェントは親の権限モードを引き継ぐため、司令塔が bypass で動くと全員が bypass になる
2. 署名鍵の用意（C-2 を採る場合）: `git config user.signingkey` と `git tag -s` が使える状態にする。ルミナスは署名鍵を持たない
3. Mac で強く分けたい場合は、ルミナス用に OS のユーザーを分ける（エージェントがユーザー設定を書けないようにする）

## 上位審査の要点（Opus、2026-10-07）

- 論点 1（目的の拡大解釈）: §4 の方向は正しいが、「Mark の指示」の定義、「従わない」の意味、停止・ロールバックを妨げない約束、進化の対象から統治の仕組みを外すこと、が欠けていた → C-1, V-1
- 論点 2（自己改変）: permissions の Edit 規則は sed -i や python の書き込みに効かず、コミット済みの改ざんは未コミット差分の警告では見えない → `guard-protected.sh`（実装済み）、承認タグ（C-2）、権限上限の固定（上記）
- 論点 3（外部送出）: 境界は「パケット」ではなく「外部AIが読めるもの全部」 → `export-public.sh`（実装済み）、V-3、確認表（support-ai §6）
- 論点 4（未検証の事実）: 本文ラベルと検証台帳の 2 本立て、失敗は止まる側へ → research-sources §6（実装済み）、V-4
- 論点 5（Jev の循環）: Jev は「止める権限」だけ。通す根拠・改善の採点に使わない。人手ラベル 100 件・ホールドアウト分離 → docs/eval-design.md（実装済み）、V-2
- 審査中の出来事: 上位審査役が Bash の cat で `.claude/settings.local.json` を読んだ（Read の deny は Bash に効かない実例。中身は MCP の allow 2 行で秘匿情報なし）。これを受けて `guard-protected.sh` が Bash 経由の鍵ファイル読み取りも止める
