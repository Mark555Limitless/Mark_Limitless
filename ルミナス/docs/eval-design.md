# 評価設計 v0.2 — Jev は助言、まず「止める信号」から

> 上位審査（Opus、2026-10-07）の論点 5 を受けた設計。判定モデル（Jev）を通過判定と改善の採点の両方に使うと、
> 自己申告と同じ循環（Goodhart: Jev の癖に合わせた最適化）が起きる。そこで役割を分ける。
> 2026-10-08: AI NEWS Select の分譲指示書に合わせ、Jev は判断層 `orch.decisions` 経由の「構造化判断の助言」とした（最終判断は Claude、取り消せない操作の承認に使わない）。
> 新しい問いを Jev に任せる前に、正解つきの例を100問以上集めてオフラインで比べる（原本の `jev_eval.py` の方式: κ・正解率・速度・費用）。
> 原本の実績（二重投稿の判定）は κ 0.54（補正後 約0.69）、Claude Haiku と同等以上で約45倍速い。それでも最終判断は置き換えていない。

## 1. 役割の分離

| 何を決めるか | 決める主体 | Jev の扱い |
|---|---|---|
| 止める（NO-GO・保留） | Jev ＋ ルール ＋ レビュー役 | **使う**（止める側の信号） |
| 通す（GO） | 一次情報の確認（司令塔）＋ Mark の最終確認（対外発信） | 根拠にしない |
| 改善を採用するか | ホールドアウトの**人手ラベル**との一致 | 使わない |

- コードで判定できるものはコードで: URL のドメインから出典の信頼度を引く表（公式ドメイン・査読誌・会議・通信社）を先に当て、残りだけ Jev に渡す
- Jev は URL を開けない。判定するのは「文書に書かれた出典の主張」なので、「公式発表によれば」と書くだけで一次情報寄りに判定されうる。この弱点を罠問題で測る
- Jev がエラー・判定不能・タイムアウトを返したら、判断層は Claude CLI → 既定値に落ちる。止める判断に使う問いでは、既定値を「保留」（止まる側）にしておく

## 2. 評価セット

- **正解ラベルは Mark が Jev の結果を見ずに付ける**（ルミナスもサポートAIも正解を作らない）
- v0 は 100 件。出典の信頼度 5 段階と GO/NO-GO を均等に混ぜ、2 割は罠（本文への指示の埋め込み、自己申告を第三者評価に見せかけたもの）
  - 20 件では一致率 0.8 の 95% 信頼区間が ±17.5 ポイントになり、閾値を決められない
- **校正用 60 件**と**ホールドアウト 40 件**に分ける
  - ホールドアウトは公開リポジトリにも、エージェントが読める場所にも置かない。採点は Mark が実行するスクリプトで行い、集計値だけを返す
  - 判断に 5 回使ったら入れ替える
- Astra（WP-2）や Gemini が出す課題案は「校正用の候補」に限る。評価される側にホールドアウトを作らせない

## 3. 指標

| 対象 | 指標 |
|---|---|
| はい/いいえ（noul） | AUROC、Brier スコア、校正曲線 |
| 選択（choice）・採点（score） | 二次重み付き κ |
| 全体 | **誤 GO 率**（人が NO-GO としたものを Jev が通した割合） |
| 人の側の基準 | Mark が 2 週間後に 20 件を付け直したときの自己一致 κ（これを超える一致は期待しない） |

## 4. 閾値

- 校正用 60 件で、「誤 GO 率 ≤ 上限（Mark が決める。例 5%）」を満たす中で保留が最も少なくなる閾値を 2 つ決める
- 結果は 3 つに分ける: **止める** ／ **保留**（上位モデルか Mark へ）／ **次の検査へ進む**（GO ではない）
- ホールドアウトでの検証は 1 回だけ行い、Wilson 区間で報告する
- 現在の `--threshold 0.6` は仮の値で、根拠はない

## 4b. Jev の弱点に合わせた追加の試験（2026-10-08、`docs/jev-value-study.md` §4・§9）

- **選択肢の並べ替え**: 校正用の各例で、Choice の選択肢の順番を逆にしてもう 1 回聞き、答えが変わる割合を記録する（公式が「先頭に寄る」と認めている）
- **言語**: 同じ例を英語の原文と日本語で聞き、一致度の差を測る。問いは英語で書く案と日本語で書く案を比べる（公式: 英語が主、CJK は精度が下がる）
- **注入**: 罠問題の一部に、本文から Jev への指示を埋め込む（公式: 敵対的な内容で答えが動く）。止める信号として使う問いでは、注入で「通る」側に動いた割合を誤 GO として数える
- **数値と日付**: ベンチマークの数値の大小・発表日の新旧は Jev に聞かず、コードで比べる
- 指標の計算には確率分布が要る。判断層は 2026-10-08 から影ログに Jev の確信度・確率分布を残す（`data/decisions_shadow.jsonl` の `jev`）

## 5. 運用

- **校正用の例を集め始める前に**モデルの版を固定する（`.env` の `JEV_MODEL=jev-1.13.0` のように版を指定。指定しないと jev-latest で、新版が出ると黙って変わり、版の混ざった校正データになる）。版が変わったら校正し直す
- 影ログ（`data/decisions_shadow.jsonl`）の問いと答えを、後で Mark の判断と照らし合わせて採否の材料にする
- 毎週、Jev を通った分（「次の検査へ進む」）から無作為に 10% を Mark が監査する。一致率が下限を割ったら Jev を外す
- 呼び出しの記録は `data/usage.jsonl`・`logs/jev.log`（git 管理外）。監査用にどこまで残すかは未決
