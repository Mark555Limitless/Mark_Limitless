## 変更
1. **（中-1）名簿の行の `caps` を使う**: `gate()` は、名簿の行の `caps` と呼び出し側（`Budget` に渡した caps）の**厳しい方**（各項目の小さい方）を適用する。知らない caps の項目名は拒否（GateDenied）。`usd_per_month`（暦月。日本時間）を扱えるようにする。名簿にも呼び出し側にも上限が 1 つも無い場合は**拒否**（上限なしで予約させない）。
2. **（中-2）行ごとに集計する**: 予約・精算の台帳の記録に名簿の行の id を含め、上限の集計は**その行の記録だけ**で行う（同じ台帳を複数の行で共有してよい）。
3. **（中-3）止めた予約の閉じ方**: `stop()` の後に古い epoch の `settle` が来たら、実額（不明なら見積り額）を「その日に 1 回だけ計上」として**閉じる**（以後は集計で見積り額を使い続けない）。2 倍超過で止まった task_id の解除は、`release(task_id, reason)` を明示的に呼んだときだけ（台帳に解除の記録を残す。呼び出しは人の操作を想定し、ゲートの自動の経路からは呼ばない）。
4. **（軽-2）** ホスト名は、非 ASCII を `lower()` より**先に**拒否する（ケルビン記号などの大文字小文字の変換で ASCII になる文字を通さない）。
5. **（軽-3）** 私的語句の照合は大文字小文字を無視する（`/users/` も C）。

## テスト（`tests/test_gate.py` に追加・修正）
- （中-1）名簿の行の `usd_per_day` を超える予約が拒否される（呼び出し側の caps が空でも）。呼び出し側の方が厳しければそちらが効く。知らない caps の項目名で拒否。上限が 1 つも無ければ拒否。`usd_per_month` の月の境界。
- （中-2）行 X の予約が行 Y の上限に数えられない。
- （中-3）stop 後の遅延の settle で閉じられた予約が、翌日以降の集計に入らない。`release` の後に同じ task_id を予約できる。release しなければ拒否のまま。
- **（中-4）複数プロセスの並行**: `multiprocessing` と `Barrier` で、上限 1 件の状態に 8 プロセスが同時に予約し、通るのが 1 件だけであること（ロックを外すと落ちる試験であること）。
- **（軽-1）日本時間の日付の境界**: 日本時間 23:59 の予約と 0:00 の予約が別の日に数えられる（時刻は注入できるようにしてよい）。
- **（軽-4）** 主な故障注入（未知ホスト・リダイレクト・区分超過・price 不明・上限超過・二重予約・detector 例外）で、`GateDenied.reason` が期待する理由であることを確かめる。
