# 名簿 v0 の項目と状態（P2、2026-10-15）

名簿は `config/roster.json`。**モデルの入れ替えは、この 1 行の変更で行う**（コードは変えない）。変更は提案→評価→Mark の承認→適用の順。承認されたら `approved_by` と承認記録（§3）を書く。

## 1. 項目（必須を絞った v0）
| 項目 | 必須 | 意味 |
|---|---|---|
| id | ○ | 行の名前（役割が分かる短い英字） |
| role | ○ | 役割（司令塔・調査役・検証役・実装役・下書き・判断の信号など） |
| provider / model | ○ | 提供元とモデル名 |
| version_kind | ○ | `snapshot`（版が固定）／`alias`（同じ名前で中身が更新される）／`unknown`（版が分からない） |
| state | ○ | `candidate` 候補／`trial` 試験中／`adopted` 採用／`hold` 保留／`rejected` 却下／`stopped` 停止／`retired` 退役 |
| max_data_class | ○ | 送ってよい最大の区分（A／B。C は誰にも送らない） |
| hosts | ○ | ゲートが許可する宛先のホスト名（ゲートを通らない相手は空） |
| price | ○ | 単価と確認日。**不明なら null（ゲートは予約できず止める）** |
| evidence | ○ | 根拠（URL・確認日・信頼度 1〜5・vendor／third_party／own_run） |
| rollback_to | ○ | 戻し先（既知の正常版。無ければ「停止」） |
| review_by | ○ | 確認期限（過ぎたら週報で「要再確認」） |
| caps / hold_reason / channel / note | 任意 | 上限・保留の理由・呼び出し経路・メモ |

後で足す候補（第 8 往復）: 保持期間・学習利用・地域・削除・サブプロセッサ、再現用の記録（プロンプト・設定・評価セットの版）、有用な完了あたり費用。

## 2. 状態の遷移
`candidate` →（自動で提案）→ `trial` →（Mark の承認）→ `adopted` → `retired`。どこからでも `hold`・`stopped` へ。
- 新しい版が見つかったら、**新しい行を `candidate` で足す**（旧版の承認は残る）。
- `alias` の重要な変更や版が不明になったら、その用途を `hold` にして再評価。旧版が使えない・安全が未確認ならその用途を `stopped`。
- 規約違反・重大な安全問題・提供終了は待たずに `stopped`。

### 切り替えの履歴（`switch_history`、最上位の任意キー）
`orch/roster.py` の `plan_switch` が、提案した名簿の辞書に `{"role", "from", "to"}` を 1 件ずつ足す。`plan_rollback` はこれを使って直前の行へ戻す。関数はファイルを書かない（名簿の保存は人が Edit で行い、確認のダイアログが出る）。

## 3. 承認記録（承認のたびに 1 件。`state/decisions/` に置く）
対象の組（提供元・モデル・版・用途・送信区分・費用上限）＋承認者・時刻・名簿の設定ハッシュ（道具が自動で計算）・有効期限・根拠の参照。

## 4. 承認が失効する範囲（Astra との第 2・3 往復で合意）
1. 版の変更: そのモデル×用途の評価と状態だけ失効。運用は戻し先で続ける。送信区分・予算・接続の承認は生きる。
2. 根拠・資料の変更: 主張の単位で「要再確認」。依存する承認・送信だけ保留。事前に決めた装飾的な項目（表示日時など）の変更は除く。
3. 安全境界そのもの（ゲート・区分の規則・調査役の定義・停止の仕組み）の変更だけが、その機能を使う処理を止める。
