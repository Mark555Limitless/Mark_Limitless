# 週報の様式 v0（P2）と、現行手順の記録の様式（P0）

## 週報（Mark が 30 分で読める。最初の 1 ページが要約、その下が根拠）
```
# ルミナス週報 YYYY-Www（期間: MM-DD〜MM-DD）
## 要約（5 行）
1. 今週の変更点: N 件（照合済み n／未確認 m／矛盾 k）
2. 名簿への提案: 昇格 a・降格 b・退役 c（無ければ「なし」）
3. 費用と時間: 調査 X トークン・Y 分（上限 15 万トークン／30 分）。API 費用 $Z
4. 判断待ち: 件数（既定値は「現行維持」）
5. 来週の範囲: 監視先 N 件＋探索枠

## 1. 変更点（1 行ずつ。ラベル: 照合済み／未確認／矛盾）
## 2. 名簿への提案（対象の行・理由・評価の結果・戻し先）
## 3. 監視の到達状況（取得失敗・古いページ・未確認。「変更なし」と「未確認」を分ける）
## 4. 判断待ち（選択肢と既定値。既定値は現行維持・保留）
## 5. 根拠（URL・確認日・信頼度）
```
- 推奨と証拠を分ける。上限を超えて調べられなかった分は「未確認」に入れ、「変更なし」と書かない。

## 現行手順の記録（P0。1 回の週次調査につき 1 枚。**司令塔が書く**＝Mark の指示 2026-10-15。Mark の関与は会話で分かる範囲〔指示・承認の回数、承認待ちの時間〕を司令塔が記録し、Mark に記入を求めない）
| 項目 | 記入 |
|---|---|
| ① 対象期間・監視先ごとの試行数・取得失敗・未確認 | |
| ② 工程・使った道具・根拠と、発表（発見）の時刻 | |
| ③ 工程ごとの人の作業時間と待ち時間 | |
| ④ モデルの呼び出し・再試行・トークン・費用 | |
| ⑤ 結果（有用・誤検知・未解決・後から分かった見落とし候補）と重大度・検知までの日数 | |
| ⑥ 人の判断・上書きと、その理由 | |
