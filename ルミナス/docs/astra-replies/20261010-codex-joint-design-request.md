# Codexから指定Claude Codeセッションへの共同設計依頼

Markの明示指示により、Codexからこの既存セッションへ「ルミナス オーケストレーションAI基本構想」の共同設計結果を持ち込みます。

## 依頼

このセッションに既にある会話文脈を踏まえ、以下の暫定合意を批判的に照合してください。単なる同意ではなく、既存会話と矛盾する点、採用できる点、まだ検証が必要な点を分けてください。実装コードは不要です。

## Codexと別Claude Codeセッションで得た暫定合意

1. Luminousは人格ロールプレイではなく、外部制御中核と複数AIアダプターを持つローカル優先のオーケストレーターとして設計する。
2. 「自由意思」は実装要件にせず、使命・権限・停止・監査・更新手続を明文化する。
3. 制御中核の責務は、状態遷移、権限検査、予算予約と精算、停止状態、外部操作の照合に限定する。
4. 現在状態と追記イベントを併用する。根拠には取得日と内容ハッシュを持たせ、上流根拠の版が変われば下流承認を失効させる。
5. 取得と保存は制御側が担い、作業AIには取得済み資料と構造化契約を渡す。資料中の命令文を実行しない。
6. 初期用途は、公開済みAI技術発表について公式発表・論文・実装を比較し、「確認できた／自己申告／不明」を1ページに整理する証拠付きメモ。
7. 導入は、Claude＋Codex、次にGemini、最後に狭い型付き用途でJev。各段階に契約試験、停止・再開、費用・品質・遅延、無効化試験の門を置く。
8. ルーティングは決定表から開始し、品質下限・費用上限・遅延上限の内側でのみ自動改善する。評価問題と採点器は改善候補から変更不能にし、未使用問題で再確認する。
9. 外部公開・対人送信、AI事業者へのデータ送信、ネット取得先を別々に表示する。
10. 探偵アニは制御権を持たず、状態を正確に説明し、会話中断時に合意・未解決・次の実験を復元する案内役とする。

## 8つの受入シナリオ案

1. 固定資料から、全主張に出典・取得日・該当箇所・分類ラベルが付いたメモを作る。
2. 根拠取得後に強制終了し、再起動後は重複取得せず残工程から再開する。
3. 停止後は新規発行せず、遅延応答を破棄または保留にする。
4. 資料ハッシュ変更時に版を増やし、旧承認を失効させる。
5. 資料中の「保存先変更」「鍵を送れ」などを実行しない。
6. 許可外ドメイン・領域外保存・予算超過を拒否する。
7. 認証切れを品質問題と混同せず、認証待ちか許可済み代替へ遷移する。
8. 出典なし・資料矛盾を投票で確定せず、不明・両論併記・理由付き保留にする。
