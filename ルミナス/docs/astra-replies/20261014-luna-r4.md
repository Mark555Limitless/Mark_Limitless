## 1. 費用・評価

- **根拠（提示された単価からの試算。実測値ではありません）**：1タスクは入力24万・出力1.6万トークン。8回を同じモデルで呼ぶと、Opus 5.5 は **$1.28**、Sonnet 5.5 は **$0.64**、GPT-6 Luna は **$0.032** です。したがって Opus が「最強の単体」だと仮定した場合：

  | 方式 | 10回実行 | 30回実行（同じ10件を3回） |
  |---|---:|---:|
  | (i) Opus単体 | $12.80 | $38.40 |
  | (ii) ルミナス | **モデル配分次第**。Opusだけで8回なら $12.80 | 同条件なら $38.40 |
  | (iii) 不一致時の多数決 | 不一致数を D とすると、下記の仮定で $1.952 × D | 同じ式。D は最大30 |

  ルミナスの1タスク費は、Opus・Sonnet・Lunaの呼出し数をそれぞれ o,s,l とし、合計8回なら **$0.16o + $0.08s + $0.004l**。ほかのモデルを使う場合、その単価も要ります。(iii) は「Opus・Sonnet・Lunaの3者が、各々8回分の予算を使う」と仮定しました。10件すべて不一致なら最大 $19.52、30回実行なら最大 $58.56。したがって(i)+(ii)が両方Opus相当なら、合計は10回で **$25.60 + $1.952D**、30回で **$76.80 + $1.952D** です。3者合計で8回に抑える意味なら別計算になり、各者の調査予算も減るため品質比較は同条件ではありません。検索料・再試行なども除外しています。

- **穴**：(iii)を不一致時だけ実行すると、全員が同じ誤りをした一致ケースを検査できません。影運用も、実際の仕事から集めた件数は独立した無作為標本とは限らず、Markの判断だけを正解ラベルにすると偏りが入ります。さらに「重大な誤GO 0件」は常に保留するだけでも達成できます。正解率だけでなく、GOの網羅率・誤NO・保留率・人の修正時間を事前定義してください。

- **0件の解釈**：10件で0件なら「この10件では観測されなかった」までです。独立試行を仮定した95%上限は片側の正確値で約26%、3/n則で約30%。同じ10件の反復は、新しい独立事例30件として数えられません。安全性や低い失敗率の証明にはなりません。

- **影運用の裁定**：Markとルミナスが互いの結果を見る前に判断と根拠を固定し、食い違いは一次資料と事前の判定規則で照合します。事実が確定できなければ「未解決／GOしない」。Markは最終決定者ですが、事実の正解ラベルはMarkの判断だけで確定しません。A相当と確認できた課題だけを対象にし、評価期間中は結果を見てルートを調整しない方が偏りを抑えられます。

## 3. 自己改善

- 評価セットへの過学習：同じ10件ではルートが癖を覚える。**固定ホールドアウトと、別期間の盲検影運用データを使い、反復回数を標本数と誤認しない**。
- 評価器や正解ラベルの汚染：改善対象が採点規則まで変えれば合格を演出できる。**評価器・ラベルを候補ルートから書換不能にし、変更は別承認・履歴付きにする**。
- 承認の形骸化：提案が増えて一括承認になる。**差分・影響・戻し方を一件ずつ示し、範囲外変更は自動停止する**。

憲章は自己改善を「提案→評価→承認→適用」と定めています。自動適用は、Markが事前承認した限定範囲内で、評価セット・候補モデル・費用上限・失敗時の復帰を固定できる場合に限るべきです。それがなければ、ルート更新は提案までに留めます。**現状の10件だけで本番ルートを自動変更する根拠は不足**しています。

## 4. 承認負荷

- 毎日の5行：①実施内容と根拠リンク、②停止中・不確実な点、③実費と残予算、④判断待ちの要点・選択肢・安全な既定値、⑤次の作業。
- 入れないもの：秘密情報、長い生ログ、定型作業の逐語報告、根拠のない精密な数値。
- 形骸化の検知：承認率・応答時間・差戻し／取消しを記録し、定期的に承認内容の理解を少数サンプルで確認します。速い承認だけで形骸化と断定しません。
- 安全側の既定値：①返答がない・内容が不明なら送信・適用しない。②費用上限超過や評価基準未達なら停止し、別モデルへ勝手に追加送信しない。

## 5. 最大の見落とし

- **根拠（評価設計）**：合格条件には「重大な誤GO 0件」と比較品質がある一方、保留をどれだけ許すかが明記されていません。**推測**：網羅率・保留率を測らないと、ほぼ何もGOしない仕組みでも「安全」と誤認し、実用性のない合格になる恐れがあります。

### 提案

- **採用推奨**：条件付きの多数決、独立した根拠による食い違い裁定、送信前の区分合成チェック。
- **要検討**：ルート自動適用の事前承認範囲、保留率・誤NOを含む合格指標、影運用サンプルの扱い。
