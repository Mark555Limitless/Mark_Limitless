## 1. 価値の核

- **反論:** H1の弱点は、出典や安全手順が付くと「正しさまで保証された」と誤解させかねないことです。一次情報を見つけても解釈を誤ることはあり、複数モデルや検証器を足せば費用・遅延・漏えい経路も増えます。すでに使えるClaude Codeと比べ、手間を増やしてまで乗り換える価値を示せるかが難所です。
- **根拠:** 憲章I-3・I-6・I-8に沿えば、ルミナスが比較できるのは引用の実在・主張との一致、予算超過や誤送信の防止、根拠・不確実性の提示といった工程品質です。基礎モデルの正答率や速度で勝つとは、比較実測なしに言えません。
- **推測:** H1を設計方針、H3を最初の用途にするのが妥当です。H2はこの試作の射程外です。「世界一」より、検証可能な一工程でClaude単体より役立つかを測るべきです。

## 2. 最初の縦切り

| 順位 | 候補 | 測定しやすさ／リスク／頻度／憲章との適合 |
|---|---|---|
| 1 | (a) ニュース検証 | 高／中／未実測／高 |
| 2 | (b) 保守係 | 高／低／週1回／高 |
| 3 | (c) 調査・要約 | 中／中／未実測／高 |
| 4 | (d) 文書下書き | 低／低／未実測／中 |
| 5 | (e) 個人データ操作 | 中／高／未実測／低 |

- **根拠:** (a)は憲章の一次情報優先を直接試せます。ただし「頻度が高い」はパケット内で実測されていません。(b)は週次・読み取り専用なので、実利用が多いなら(a)より先でもよいでしょう。
- **(a)の指標案:** 引用の実在率・主張を支持する割合・適切な保留率を測り、重大な誤GOを0件にする。Markの判断だけを正解にすると個人の期待に偏り、事実判定と「発信してよいか」という価値判断も混ざります。採点基準と曖昧例の扱いを先に定め、可能なら別の評価者にも盲検採点を依頼してください。10件×3回は同じ10件の反復であり、30件の独立評価ではありません。

## 3. 「十分に高性能」の合格ルール案

`重大な誤GO = 0` **かつ** `Q_ルミナス ≥ Q_最強単体 − 10ポイント` **かつ** `総費用 ≤ Y` **かつ** `人の修正時間 ≤ Z` をすべて満たすこと。

- **根拠と推測:** 10件なら1件の差が10ポイントです。したがってX=10ポイントは試作の粗い許容幅で、優位性の統計的証明にはなりません。Yは試験前に決める枠とし、暫定案を**総額1ドル**、Geminiは**1日0.25ドル以内**とします。Zは**1件5分以内、かつClaude単体より長くない**を提案します。いずれも測定後に都合よく変えないことが重要です。
- **費用試算:** 90回を「各1 API呼び出し」、1回あたり入力5,000・出力1,000トークン、キャッシュ・検索・再試行なしと仮定。GPT-6 Luna **$0.09**、DeepSeek Flash **$0.243**、Sonnetまたは導入価格中のGemini **$1.80**、Opus **$3.60**。Geminiは通常価格になると90回で**$3.60**です。公式表はGPT-6 Lunaの単価を[OpenAI API価格表](https://developers.openai.com/api/docs/pricing)、Opus/Sonnetを[Anthropic API価格表](https://platform.claude.com/docs/en/about-claude/pricing)、Geminiの導入価格と改定日を[Googleのモデル価格情報](https://ai.google.dev/gemini-api/docs/latest-model)で照合しました。
- Geminiを30回だけ使っても、この仮定では$0.60となり、1日上限を超えます。90回はLunaだけなら小額ですが、上位モデルや検索を含めると小予算とは限りません。**90回が手順の完了数なら、API呼び出し数はさらに増えます。**多数決は30完了分だけで90呼び出し、ルミナスの内部呼び出しも加算が必要です。
- 同トークン数の単体多数決を入れる意味は、ルミナスの改善が司令塔や検証工程によるものか、単に追加トークンを使った結果かを切り分けることです。反復した入力トークン、出力上限、検索などのツール費用もそろえてください。

## 4. ルーティング v0

| 失敗 | 処置 |
|---|---|
| 認証切れ | 停止。認証修復を待つ |
| 上限・予算到達 | 停止。上位や安価な別モデルへ迂回しない |
| 品質不足 | 事前評価済みの上位モデルへ1回。なお不足なら保留 |
| 形式不正 | 同モデルで形式修正を1回。再失敗なら停止 |
| 時間切れ | 未受理と確認できた場合だけ同モデルで1回。状態不明なら停止 |

品質判定はモデル自身の「疑い」ではなく、固定した評価規則に基づけます。候補をまず品質基準で絞り、その中から最安を選ぶ設計なら、安さのために品質不足を隠す降格を防げます。

1. 収集目的・保存期間・第三者提供を明示し、削除手段と同意を用意する。

5. 提供者の規約、出典やデータの利用条件、対象地域の法令を確認する。
