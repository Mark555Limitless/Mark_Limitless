# ADR 2026-10-08: Codex の基本構想 v0.2 への回答に対する Mark の決定

元: `docs/proposals/20261008-codex-proposal-response.md` §6。Mark がチャットで 5 点を決めた（2026-10-08 夜）。

## 1. 実行の制御を独立した部品にする（最初はファイルで）
- 背景: 安全の仕組みが hooks・ラッパー・上限に分かれ、全体を止める印も予算の予約も外部操作の状態も無かった
- 選択肢: (A) 今のまま (B) 独立した部品にし、常駐の管理プロセスと SQLite で作る (C) 独立した部品にし、最初はファイルで作る
- 決定: (C)
- 理由: 外部AIの実呼び出しはまだ 0 件で、規模はファイルで足りる見込み。動くものを増やすと Mark が状態を見分けにくい
- 影響: 最初の一歩は全体の停止の印（`docs/specs/20261008_global_halt.md`）。管理プロセスは Phase 1 の評価で件数を測ってから
- 未決: 実装を Mac の Codex で行うか、クラウドの司令塔で行うか。印はその機械の中でしか効かない（Mac で止めてもクラウドは止まらない）。機械をまたぐ停止は Phase 2

## 2. 鍵の控えの置き場所はいったん今のまま
- 背景: `tools/set_env_key.sh` が鍵を書き換えるたびに `.env` の平文の写しを非公開フォルダに残す。キーチェーンへ移す案を出した
- 決定: 今のまま（非公開フォルダの控え）
- 影響: 変更なし。写しが回数分増える点は残るリスクとして記録し、見直すときに再提案する

## 3. Codex のファイルの場所
- Mark の依頼: `COMMON_RULES.md` と `architecture-reviewer.md` の場所を開いてほしい
- 状況: Mark の Mac の Codex の提案フォルダにだけあり、GitHub（このリポジトリ・Obsidian のリポジトリ）には無い。クラウドの司令塔からは開けないので、Mac で動いている AI NEWS Select の司令塔のセッションに、`mdfind` で探して Finder で表示し Mark に伝えるよう頼んだ（読むだけ）
- 次: 場所が分かったら中身をこのリポジトリに取り込み、CLAUDE.md と照らして「共通ルールの正典を 1 つにする」を決める

## 4. 原本の不具合を Fable5 の司令塔に伝える
- 決定: 伝える
- 実施: 2026-10-08、Mac の AI NEWS Select の司令塔のセッションに連絡を送った（Jev の Score の扱い・Codex の再試行。まず Score を使っているかの確認を頼み、ルミナスの修正の場所を参考として示した）。原本はルミナスから変えない

## 5. 自走の範囲を広げる
- 背景: 憲章 I-5 は自走範囲の中なら取り消せない操作も許すが、`VIRTUAL_MARK.md` §3 は公開・送信・課金・削除を常に確認にしていた
- 決定: 広げる
- 実施の形: `VIRTUAL_MARK.md` に許可台帳（§7）を作り、Mark が載せた行の範囲（対象・上限・期限・条件）の中だけ確認なしにする。台帳は空から始める。差分は `docs/proposals/20261008-autonomy-grants.md`
- 司令塔の推奨は「今は広げない」だった（回答 §6-5）。主な危険: AI が自分で範囲を広げる・偽の指示で行が足される・送ったか分からないまま繰り返す
- 状態: **未適用**。差分 v0.1 は Opus の反証審査で REJECT（重大 4）。v0.2 は全件を反映し、適用の前提（hooks が効く環境の確認・全体停止の実装と確認・台帳を Mark 自身の操作で変える方法）を先に満たす順番にした
- **逸脱の記録（なぜ・何を・今後）**: 司令塔は、差分を出して文面の承認を受ける前に、保護ファイル 3 つ（`VIRTUAL_MARK.md`・`CLAUDE.md`・最終プロンプト）を直接書き換えようとした。CLAUDE.md「変更の進め方」と憲章 §4 からの逸脱。なぜ: Mark の「広げる」を、文面の承認と取り違えた。何を: Claude Code の自動モードの安全確認が止め、何も変わっていないことを確かめた。決まりどおり差分の提案に切り替えた。今後: 保護ファイルの変更は、方向の決定があっても、必ず差分の文面を Mark に見せて承認を受けてから行う
