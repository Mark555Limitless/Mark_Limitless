# ADR 2026-10-10: 許可台帳（自走の範囲を広げる）— Mark の決定 4 点

元: `docs/proposals/20261008-autonomy-grants.md` §5「Mark に決めてほしいこと」。Mark がチャットで決めた（原文「1.おすすめで　2.おすすめで　3. いったんTouch ID などの鍵で承認する方法」でしばらく様子を見ましょう。　4.Mac」）。

## 1. 順番 → 推奨どおり（はい）
- §1 の前提を先に満たす: (1) Mac の正本で `claude` を起動して hooks が効くことを確かめる → (2) 全体の停止 A・B を実装して Mac で止まることを確かめる（A は 2026-10-10 にコミット済み。B は差分の案を Mark が承認してから適用）→ (3) 台帳の変更を Mark 自身の操作に限る方法を用意する → (4) 仕上げの反証審査 → (5) 差分を Mark の承認で適用。台帳は空から始まる

## 2. クラウドでも hooks を効かせるか → 推奨 (a): 効かせない
- 影響: 許可台帳はクラウドのセッションでは使わない。クラウドは調査・起草・対話の窓口（Phase の決定 2「司令塔は Mac」と一致）。クラウドの保護ファイルの守りは Claude Code の自動モードの安全確認と git の pre-commit・pre-push に頼る（§0）

## 3. 台帳を Mark 自身の操作で変える方法 → (a) 署名つきの承認タグ。鍵は Touch ID などで守られたもの。「いったん…でしばらく様子を見る」
- 影響: 鍵は Mark 本人が作る（使うたびに Mark の操作が要るもの）。AI は手順の文書を書くだけ。Mark の鍵の指紋を保護ファイルに固定し、`git verify-tag --raw` の署名者の指紋が一致するタグだけを承認とみなす。guard-protected で AI の `git tag`・`git config`（`gpg.*`・`user.signingkey`・`gpg.ssh.allowedSignersFile`）・`ssh-keygen -Y sign`・`ssh-add` を止める（B の差分とは別に、台帳の適用時の差分に入れる）
- 「しばらく様子を見る」: 運用して手間が重すぎれば見直す。見直すときも (b)（GitHub の Web 編集）・(c)（Mac の確認画面だけ）は「確かめられないので台帳は空のまま」の扱いを変えない
- 次の一手: 鍵の方式（Secure Enclave の鍵・1Password の SSH agent・ハードウェアキー・パスフレーズ付き鍵）の事実確認を一次情報で行い、Mark 向けの手順書 `docs/mark-signing-key.md` を書く（司令塔が起草、文書の審査を通す）

## 4. 最初に台帳に載せたい操作 → 「Mac」
- 読み方（司令塔の解釈。**Mark に確認する**）: 最初の行は「Mac の中で完結する操作」に限る、と読む。候補: Mac での `tools/codex_impl.sh` の実行（Codex への指示書の送出）、Mac のローカルのコミット、docx の再生成、Obsidian の vault への同期。外部への公開・送信・課金（PR の作成・push・メッセージ・支払い）は最初の行に載せない
- 別の読み方: 「台帳を使う場所は Mac」（決定 2 の再確認）。この場合、最初に載せる操作は未決のまま
- どちらの読みでも、台帳は前提（§1）を満たすまで空のまま
